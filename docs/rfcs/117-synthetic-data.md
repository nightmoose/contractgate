# RFC-117: Synthetic data from a contract

**Status:** Accepted
**Date:** 2026-11-25

## Problem

Teams want test rows for a pipeline before real data exists, or without copying production data into a test environment. They also want rows that fail in known ways, to check that their quarantine and alerting paths work. Hand-written fixtures drift from the contract.

## Decision

Generate rows from the contract alone.

- Inputs are the contract's rules: field types, `required`, `enum`, `min`/`max`, `min_length`/`max_length`, `pattern`, `format` (`email`, `uuid`, `uri`/`url`), `date` and `timestamp` types, nested objects, arrays, quality rules (`completeness`, `freshness`, `uniqueness`), field-bound `metrics` and `compliance_mode`. Stored events, quarantine rows and any other real sample are never read.
- The validator is the oracle. Each candidate value is checked against a one-field contract, and each finished row against the full contract plus batch uniqueness. A row is only returned when the validator agrees.
- Patterns are generated by walking the regex syntax tree (`regex-syntax`, the parser `regex` itself uses), not by guessing.
- When a rule cannot be met (for example `min_length: 5` with `max_length: 3`, or `uniqueness` on a boolean across 5 rows), generation stops with an error that names the rule and field. No partial or bad rows are returned.
- `invalid` mode builds a valid row, then breaks one rule. The row is kept only when the validator reports exactly one violation and it is that rule. Each row carries a `broken_rule` label. Rules that cannot break alone (a missing field that a metric also reads, for example) are listed in `skipped_rules`.
- Output is deterministic for a given seed, contract and engine version. The only outside input is the clock, used for `freshness` windows.
- Rows per call: 1 to 10,000.

Surfaces: `POST /contracts/synth` (contract inline or by id, API key required, nothing written) and `contractgate synth` (local, no network).

## Not in v1

All three are addressed in [RFC-118](118-synthetic-data-v1-1.md).

- Cross-field rules such as "end date after start date". The contract format has no cross-field rule today, so the generator has nothing to read. When the format gains one, the generator should follow it.
- Breaking rules inside array items in `invalid` mode. Items are generated valid.
- Envelope wrappers (RFC-038). Rows are the inner records.
